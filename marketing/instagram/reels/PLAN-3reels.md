### Reel 1 ｜ ダイニングの上、ペンダントかダウンライトか

**使用する間取り**: `public/demo/share-demo-project.json`（8.6×6.4m、天井2.42m、10/15 20:00、daylight OFF）
唯一「寸法入り間取り図」を背景に持つ、日本の新築LDKに最も近いデモ。

**対象施主と状況**
間取りが確定し、電気図面に照明記号が入った段階。ダイニングは丸テーブル1200。
工務店の標準仕様はダウンライト、施主側はペンダントに憧れがある、という典型的な分岐点。

**実際に迷う判断**
食卓の真上を、ペンダント1灯にするか、ダウンライト2灯にするか。

**なぜ両方が候補になるか【事実ベース】**
- ペンダント: 食卓面に光が集中する。器具そのものがインテリアになる。一方でテーブル位置が固定される。
- ダウンライト: 天井面がすっきりする。テーブルを動かしても影響が小さい。一方で食卓の陰影は平坦になりやすい。
どちらも実際に施工される標準的な選択肢であり、優劣ではなく条件依存。

**固定する条件**
部屋・壁・窓・家具の位置、リビングDL3灯（520lm / 2700K / 調光28）、キッチンDL3灯（760lm / 3500K / 調光82）、
階段ブラケット（360lm）、TV背面テープライト（420lm / 2400K）、色温度2700K、カメラ経路、露出。

**変更する条件（1つだけ）**
食卓直上の器具のみ。
- A = `light-dining-pendant`（ペンダント / 940lm / 2700K / 調光92 / コード0.8m、テーブル面から約0.90m上）
- B = 中角ダウンライト2灯（`dl-medium` / 520lm×2 / 2700K / 天井 y=2.38、テーブル中心 x=-1.35, z=0.95 を挟む配置）

**この比較で判断できること**
食卓に座った人と料理への光の当たり方、天井の見え方、テーブルの外側がどこまで暗くなるか。

**Lighting Lab へつながる因果**
「A/Bの差は、テーブルのサイズと位置で変わる」→ 自分の家は丸1200か長方形1800か → 図面ではどちらも記号1つ →
自分の間取りで見ないと決められない → プロフィールのリンク。

**対象施主と状況**

**および時間送りのカーブ（上下で完全に同一）**。

**変更する条件（1つだけ）**
縁側の建築化照明3本の ON / OFF のみ。上段=あり、下段=なし。

**時間の扱い**
`daylight.enabled` を **ON** にし、10/20 の 16:30 → 18:30 を上下同時に送る。
時間は比較変数ではなく、**上下に共通して与える文脈**。変数は建築化照明の有無だけ。

**この比較で判断できること**
外がまだ明るい時間には差が出ないこと、暗くなるにつれて窓の見え方と縁側の奥行きに差が出ること。

**Lighting Lab へつながる因果**
「差が出るのは時間帯による」→ うちの窓はどっちを向いていて、何時に暗くなるのか →
方位と時刻を変えて見ないと分からない → Lighting Labは月日・時刻・方位・緯度を持っている → プロフィールのリンク。

**この1本を入れる理由**: 既存素材（カルーセル3本＋リール2本）が**すべて夜**。
Lighting Labが夜専用ツールに見えている状態を、製品の実機能（`Daylight`）で打ち消す。

## 5. 各企画を選んだ理由

**Reel 1 を最優先にする理由**
ダイニングの器具種別は、電気打ち合わせで**ほぼ全員が通る**分岐。かつ既存投稿5本のいずれとも重複しない
（既存は色温度3本、後悔リスト1本、間取り紹介1本）。使用するのは唯一の寸法入りデモLDKで、
日本の新築施主が自分の家に置き換えやすい。

**Reel 2 を2番目にする理由**
吹き抜けは「後から直せない」度合いが最も高く、事前比較の必要性を説明しやすい。
比較対象の2案が**すでに同じデモJSONに両方入っている**ため、動画のために不自然な条件を作らずに済む。
また Reel 1 が水平方向の判断（食卓の上）なのに対し、これは垂直方向の判断で、映像構成が自然に変わる。

**Reel 3 を3番目にする理由**
既存素材が全て夜であることが、製品の positioning を狭めている。これは投稿テーマの問題ではなく
**製品理解の問題**なので、優先度は高い。上下分割＋時間送りという構成は、
「時間によって答えが変わる＝一般解が存在しない」という Lighting Lab の中心主張と構造が一致する。

**構図が3本とも違う理由（結果であって目的ではない）**
- Reel 1 の判断は「食卓に座ったときどう見えるか」→ 寄っていく必要がある → ドリーイン。
- Reel 2 の判断は「上まで光が届くか」→ 縦に追う必要がある → チルトアップ。
- Reel 3 の判断は「時間で差がどう変わるか」→ 同時に並べないと分からない → 固定カメラ＋上下分割。

## 7. 制作にあたって必要になる実装（承認後）

既存の `capture-decision-reel.mjs` の3モードでは、上記3本はいずれも撮影できない。

| モード | 現状 | 必要な追加 |
|---|---|---|
| `stacked-light-compare` | 比較側の照明を**等間隔ダウンライトのグリッドに置換**する固定実装 | Reel 3 には使えない。上下で「指定IDのON/OFFのみ」を変え、`daylight.hour` を同時に送るモードが必要 |
| `light-toggle-slide` | 指定IDを途中でONにしつつ**横スライド** | Reel 1/2 のドリーイン・チルトに対応しない。器具の**追加/差し替え**にも対応しない |
| `light-property-animation` | `cordLengthM` と `y` の補間のみ | 該当なし |

**実装済み（承認後に追加）。当初3モードの想定だったが2モードに集約した。**
Reel 1 のドリーインと Reel 2 のチルトアップは、どちらも「バリアントを切り替えながら
カメラを補間する」処理で、別モードにすると同じコードが二重になるため。

1. `fixture-variant-move` — 器具バリアントの切替＋カメラ補間（Reel 1 / Reel 2 / Reel 3のoutro）
   カメラの from と to を同じ値にすれば、同一フレームでのA/B切替になる。
2. `daylight-split-timelapse` — 上下分割で `daylight.hour` を同時送り。変数は上下のバリアント差のみ（Reel 3）

バリアントは「無効化 `disableLightIds` / 数値の上書き `lightOverrides` / 追加 `addLights`」の
3操作だけで表す。既存方針（各shot開始時に元JSONを読み直し、変更はメモリ上のみ）を踏襲。
**元のデモJSONは変更していない。**

実施済みのその他の変更:
- 免責のフォントサイズを **22px → 26px**、不透明度 0.74 → 0.82（`encode-reel.mjs`）
- 出力ファイル名（既存を上書きしない）:
  `reel-dining-pendant-vs-downlight.mp4` / `reel-void-pendant-vs-spot.mp4` / `reel-engawa-cove-dusk.mp4`

### 比較を成立させるための光束の扱い【重要】

「片方が明るいだけ」の絵にしないため、**同じ役割を別の手段で果たす比較では全灯の合計光束を揃えた**。
検算値（`lumens × dimmer / 100` の総和。`src/utils/lighting.ts:68` の実装どおり）:

| Reel | バリアント | 合計光束 | 差 |
|---|---|---|---|
| 1 | ペンダント / ダウンライト2灯 | 3591.2 lm / 3589.6 lm | 0.04% |
| 2 | 長いペンダント / 壁向きスポット2本 | 3345.6 lm / 3349.2 lm | 0.11% |
| 3 | 縁側の間接あり / なし | 4248.4 lm / 3341.2 lm | **揃えない** |

Reel 2 は揃えるために `dimmer` を調整している（ペンダント 76→95、スポット 72/70→58 各）。
これは第2の変数ではなく、**総光束を固定するための操作**。
Reel 3 だけ揃えないのは、「器具を足すか足さないか」が判断そのものであり、
光束差を消すと比較が無意味になるため。
