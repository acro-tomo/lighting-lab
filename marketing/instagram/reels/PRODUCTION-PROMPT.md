# リール制作プロンプト

[next-four-reels.md](next-four-reels.md) の4本を実際に mp4 にするために、
新しいセッションへそのまま貼るプロンプト集。

**使い方**: 別ターミナルで `npm run dev` を起動しておき、
「共通ルール」＋「作りたい1本のブロック」を続けて貼る。**1セッションで1本だけ作る**
（撮影は数分単位でかかり、複数本を並行させるとフレームディレクトリが混ざる）。

---

## 共通ルール（毎回、案のブロックの前に貼る）

```
LDK Lighting Lab の Instagram リールを1本作る。設計は
marketing/instagram/reels/next-four-reels.md、リールの規約は
marketing/instagram/reels/AUDIENCE-AND-FORMAT.md にある。**両方を先に読むこと。**
両者が食い違う点は next-four-reels.md の冒頭「AUDIENCE-AND-FORMAT.md との関係」に
引き継ぐ項目と上書きする項目が整理してあるので、それに従う。

## 前提
- 別ターミナルで `npm run dev` が起動済み（http://127.0.0.1:5173/）。
- 撮影は scripts/instagram/capture-decision-reel.mjs、エンコードは
  scripts/instagram/encode-reel.mjs を使う。どちらも REEL_CONFIG で設定ファイルを渡す。
- 初回のみ `npm run ig:fonts` でフォントを取得する（fonts/ は .gitignore 済み）。

## 絶対に守ること
- 実照度(lux)・IES/LDT配光・照度計算書を保証する表現を、テロップにもキャプションにも入れない。
  メーカー名・型番・価格も出さない。CLAUDE.md の誠実性の不変条件。
- テロップは 1画面1文・全角14文字以内。設計ファイルの文言を勝手に増やさない。
- **構図規約（AUDIENCE-AND-FORMAT.md）を守る。テロップは y=1000〜1500 に載るので、
  主役は画面の上半分（y<1000）に収める。天井が主役でも見上げず、ピッチを下げて
  天井を上半分へ持ち上げる。**
- 比較で条件を変えるときは、バリアント間で合計光束（lumens × dimmer / 100 の総和）を
  0.1%以内に揃える。案A・案Bは照明を1つも変えないので自動的に満たす。
- 冒頭2秒はテキストもロックアップも一切乗せない。これがこの4本の主目的なので、
  「見出しがないと分かりにくい」等の理由で足さない。
- 音声は入れない（REEL_WITH_VOICE は使わない）。ナレーションは実測5.8字/秒で、
  1.5秒ショットには (1.5-0.4)×5.8 ≒ 6字しか入らない。尺を9〜12秒にした時点で成立しない。
  既存21本は全てAI音声入りなので、無音であること自体も検証したい変数になる。
- ディスク上のデモJSON（public/demo/rooms/*.json）は書き換えない。
  比較条件はメモリ上のプロジェクトへ適用する。
- 生成物のうち mp4 と設定JSONだけをコミットする。output/ 以下（中間フレーム）はコミットしない。
- このブランチの内容を staging / main へマージしない（SNS素材のため）。

## パイプラインに必要な変更（設計ファイル6節）
現行の encode-reel.mjs は全フレームに scrim + ロックアップ + eyebrow + 見出し + sub を
固定で乗せる（scripts/instagram/encode-reel.mjs:96-175）。次の2点を先に実装する。

1. text.silent = true のショットでは、完全に透明なオーバーレイを出す
   （scrim もロックアップも文字も無し）。shots.filter は TEXTS[shot.id] の存在で
   フィルタしているので（:196-201）、text を省略するのではなく silent フラグで表現する。
2. eyebrow / sub / cta を省略可能にする。現状は未定義でも <p> が描画されて
   "undefined" が出る。1画面1文にするため headline 1行だけで成立させる。

あわせて、ショット間のクロスフェードが定数 XFADE = 0.4 秒で固定されている（:29）。
1.5〜2.0秒のショットが並ぶので、config から上書きできるようにして 0.2 を既定にする。

## 進め方（この順を守る）
1. 設計ファイルの該当ブロックを読み、reel config を書く。
2. `REEL_CONFIG=<config> REEL_SMOKE=1 npm run ig:decision-capture` で3フレームだけ撮り、
   構図を確認する。ここで破綻していたらカメラ値を直してやり直す。本撮影に進まない。
3. 本撮影 → エンコード。
4. 出力 mp4 の 0.0 / 1.9 / 2.1 / 中盤 / 末尾 のフレームを書き出して目視で確認し、
   何が映っているかを文章で報告する。「できました」だけで終わらせない。
5. 判断できない点は「要確認」と明示する。推測でパスやAPIを作らない。

## 受け入れ基準
- 尺が設計どおり（±0.5秒）。
- 0.0〜1.9秒のフレームに文字・ロックアップ・暗幕が一切写っていない。
- 各テロップが全角14文字以内で、1画面に1文だけ。
- 末尾にURLと免責が出ている。
- 実照度を保証する表現がどこにも無い。
```

## 案A｜天井に穴が1つもない部屋（最初に作る）

```
案A「天井に穴が1つもない部屋」を作る。10.5秒・無音。

## 素材
public/demo/rooms/dk-copenhagen-apartment.json をそのまま使う。
ダウンライト0灯、ペンダント5＋ブラケット4の計9灯。8.6m × 6.4m / 天井3.25m。
この部屋を選ぶ理由は「天井に穴が1つも無い」ことなので、照明は一切足さない・消さない。

## 必要な実装
capture-decision-reel.mjs の sequence.mode に camera-animation を追加する。
現状は lights を動かす3モードしか無い（:209-216）。追加するモードは
project は不変のまま、camera.position / camera.target をフレーム毎に補間して
canvas を撮るだけでよい。補間は既存の lerp / eased をそのまま使う。
静止ショットは from と to を同じ値にすれば表現できるので、専用モードは作らない。

## ショット構成
| id | 秒 | カメラ | テロップ |
|---|---|---|---|
| a1-ceiling  | 2.0 | 天井が画面上半分を占める位置から下降開始（**見上げない**） | なし（silent） |
| a2-descend  | 1.5 | 下降continue | 天井に穴がありません |
| a3-fixtures | 2.0 | 低いペンダントとブラケットが順に入る | 灯りは9つあります |
| a4-wide     | 2.0 | 部屋全体の引き | どれも低い位置です |
| a5-seated   | 2.0 | 座位目線（y=1.15前後）で静止 | これで暗いと思う？ |
| a6-outro    | 1.0 | 静止 | outro（URL＋免責） |

最後のテロップは問いのまま終える。答えを書き足さない。これがこの案の唯一の狙い。

## カメラ初期値（要調整。SMOKE で見て直す）
JSON の既定カメラは position {x:3.35, y:1.5, z:2.35} / target {x:-1.4, y:1.15, z:-1.2}。
天井高は 3.25m。**a1 でも見上げない。** カメラを天井近く（y≒2.6）に上げ、
target を position より少し低く置いて**わずかに見下ろすピッチ**にすると、
天井が画面の上半分に入りテロップ帯（y=1000〜1500）と競合しない。おおよそ

  a1 from: position {x:2.9, y:2.60, z:1.9}, target {x:-1.6, y:2.35, z:-1.6}
  a1 to:   position {x:3.1, y:2.15, z:2.0}, target {x:-1.5, y:1.85, z:-1.5}

から試す。a5 は既定カメラに戻す。値は必ず REEL_SMOKE で確認してから本撮影する。
確認するのは「天井の無傷な面が上半分に写っているか」と「target.y < position.y になっているか」の2点。

## 出力
- config: marketing/instagram/reels/a-no-downlights.reel.json
- framesDir: output/reel-a-no-downlights-frames
- outName: reel-a-no-downlights.mp4

## 要確認（分かったら報告する）
- 天井を舐めるカットで天井面が破綻せず映るか。ラスター編集表示のバウンス近似
  （src/components/scene3d/lightingFill.ts:23-31）は光束と床面積のみの関数で
  マテリアル色を見ていないため、天井がのっぺりするか陰影が出るかは撮ってみないと分からない。
  破綻する場合は a1 を「天井の一部＋ペンダントの上端」の構図に寄せて回避する。
- 0灯を強調する構図で天井が黒く潰れすぎないか。潰れる場合は camera.exposure を上げる前に
  カメラ位置でペンダントとの距離を詰める。
```

## 案B｜図面の目線と、座ったときの目線

```
案B「図面の目線と、座ったときの目線」を作る。10秒・無音。
案Aで追加した camera-animation モードをそのまま使う。

## 素材
public/demo/rooms/jp-hiraya-engawa.json（12m × 7.2m / 天井2.4m /
ダウンライト4灯＋折り上げの間接照明）を使う。日本の注文住宅に最も近い間取りのため。

## ショット構成
| id | 秒 | 画 | テロップ |
|---|---|---|---|
| b1-plan    | 2.0 | ほぼ真上の俯瞰から降下開始。壁が起き上がってくる | なし（silent） |
| b2-descend | 1.5 | 降下continue | 図面はこの高さです |
| b3-seated  | 2.5 | 座位高さ（床上約1.15m）で停止 | 座るとこう見えます |
| b4-look    | 2.0 | position は固定、target だけ振って器具が視界に入る | 器具が視界に入ります |
| b5-hold    | 1.0 | 静止 | 照明は変えてません |
| b6-outro   | 1.0 | 静止 | outro（URL＋免責） |

## 守ること
- 照明のパラメータは1つも変えない。変えるのはカメラだけ。それがこの案の主張。
- 「眩しい」「グレア」と断定しない。テロップは「器具が視界に入ります」まで。
  ラスター表示で眩しさがどう出るかは未検証のため。

## 要確認
- 俯瞰の b1 で天井をどう扱うか。setShowCeiling は瞬時切替でフェードできない可能性が高い。
  天井ありのままカメラを高く引いて成立するなら、それを優先する（切替の実装を足さない）。
- 俯瞰から座位までを1本の補間で繋いだとき、途中で壁を突き抜けないか。
  突き抜けるなら中間キーフレームを1つ足す。

## 出力
- config: marketing/instagram/reels/b-eye-height.reel.json
- framesDir: output/reel-b-eye-height-frames
- outName: reel-b-eye-height.mp4

## 案C｜指で動かすと、3Dが同時に変わる

```
案C「指で動かすと、3Dが同時に変わる」を作る。11秒・無音。
4本の中で新規実装が最も多い。まず要確認3点を潰してから撮影に入る。

## この案が他と違う点
これはアプリの画面録画で、レンダーだけの映像ではない。既存21本には一度も
画面UIが映っていないので、アカウント内で明確に別種になることが狙い。
照明の論点は1つも主張しない。主張するのは「自分で動かせる」だけ。

## 先に確認する3点（撮影より先。分かったことを報告してから進む）
1. 1080×1920（撮影ビューポートは 1280×2276）で 2D平面図と 3Dビューが
   同時に成立するレイアウトになるか。現行の capture-decision-reel.mjs は
   `.focus-toggle[aria-label="3Dを最大化"]` を押して3Dだけにしている（:198前後）。
   同時表示の縦長構図が成立しないなら、上下2分割は諦めて
   「平面図のみ→3Dのみ」の切り替えで見せる構成に変える。
2. 撮影方法。現行は locator("canvas").first() を clip して撮るため
   SVGの平面図が入らない（:82-86）。UI全体を page.screenshot で撮る経路を追加する。
   その際 HIDE_CHROME_CSS は使わない（UIを見せるのが目的）。
   ただしフィードバック導線・自動保存の注記など、動画に出したくない要素だけは隠す。
3. 指カーソル。Playwright のポインタは描画されないので合成が要る。
   現行パイプラインに指カーソル合成は無い。丸い半透明のドットを
   オーバーレイHTML側で座標指定して重ねる方式が最も安く済む。

## ショット構成（上下2分割が成立した場合）
| id | 秒 | 操作 | テロップ |
|---|---|---|---|
| c1-drag   | 2.0 | 平面図のダウンライトを1つ掴んで横へ引く。3Dの光だまりが同時に動く | なし（silent） |
| c2-drag2  | 1.5 | ドラッグcontinue | 触ると同時に変わります |
| c3-slider | 2.0 | インスペクタの調光スライダーを動かす | 明るさもその場で |
| c4-off    | 2.5 | 照明を1つ消して部屋の一角が沈む | 1灯消すとこうなる |
| c5-arrive | 2.0 | リンクを開いた直後の画面（部屋を選ぶ→部屋が出る） | 開くとこの画面です |
| c6-outro  | 1.0 | 静止 | outro（URL＋免責） |

## 参考実装
scripts/demo-video/capture-ui-frames.mjs:104-161 が、実クリック＋平面図の照明選択＋
インスペクタのスライダー操作を1フレームずつ撮る手順を実証している。これを土台にする。

## 出力
- config: marketing/instagram/reels/c-touch.reel.json
- framesDir: output/reel-c-touch-frames
- outName: reel-c-touch.mp4

## 案D｜床の色を変えただけ（着手前に検証が必要）

```
案D「床の色を変えただけ」は、成立するかどうかの検証から始める。
撮影スクリプトを書く前に、次を確認して報告すること。

## なぜ検証が先か
ラスター編集表示のバウンス近似（src/components/scene3d/lightingFill.ts:23-31 の
rasterBounceIntensity）は光束と床面積だけの関数で、マテリアルの色を参照していない。
床を暗くしても間接的な明るさは変わらない設計になっている。
反射の相互作用はパストレ側の効果で、しかも現行の撮影スクリプトは
capture-plates.mjs も capture-decision-reel.mjs も全てラスター表示のスクリーンショットで、
パストレ表示を撮る経路が存在しない。

## 検証手順
1. 適当なデモ部屋を開き、ヘッダーの「レンダリング開始」で床が明るいオークのPNGを1枚書き出す。
2. 床のマテリアルの baseColor だけを濃い色へ変え、同じカメラでもう1枚書き出す。
3. **目視で判定しない。** AUDIENCE-AND-FORMAT.md の「成立しなかった軸」と同じ方法
   （1080相当へ縮小してRGB差を取り、|Δ|>12 の画素の割合）で測り、数値を報告する。

判定の目安は **40%以上で成立**。記録されている水準は、数灯の色温度変更が0.1〜2%（絵にならない）、
ロフトの5灯が22〜36%（見た目は弱い）、採用済みの第3弾⑧が92%、全灯2700K→6500Kの対照が99%。
36%以下ならこの案は捨てる。無理に成立させない。

## 差が出た場合の作り方
撮影スクリプトは書かない。書き出した3〜4枚のPNGを ffmpeg でクロスフェードして
連番フレームにし、既存の encode-reel.mjs でテロップを乗せる。追加実装ゼロ。
最終レンダーPNGには右下に透かしが入る（src/app/appUtils.ts:17-27）ので、
テロップのレイアウトがそれと重ならないか確認する。

## 確認すること
- 床のマテリアルがデモ部屋JSONで単一の materialId に紐づいているか。
  床が複数マテリアルに分かれていると1色変えても効かない。
- 壁の色を変える3本目・4本目のPNGも同じカメラ・同じ照明で書き出せているか。

## 出力
- outName: reel-d-floor-color.mp4
```

## 投稿まわり（4本共通）

- **CTAは「自分の間取り図を読み込んで」にしない。**「リンクを開くとこの部屋が出ます」に限定する。
  壁の自動認識は未実装で、自分の図面から始める経路はリール直後に踏める行動ではない。
- bioのリンクは `?demo=<key>` の直リンクにする（案Aなら `?demo=copenhagen`）。
  動画で見た部屋がそのまま開く。`src/app/hooks/useProjectPersistence.ts:30` で実装済み。
- キャプションの型と免責は [docs/instagram-playbook.md](../../../docs/instagram-playbook.md) 5節に従う。
- 入稿は [BUFFER-QUEUE.md](../BUFFER-QUEUE.md) と同じ形式で追記する。
